# 课件提示词

把下面整段发给 AI，改掉第一行的主题即可。在本仓库里说“做下一课”时，AI 也按这份要求做。

---

请做一节 Python 课：**【主题，例如：if 判断】**

## 学生和老师

- 学生是小学高年级和初中生，零基础起步，Windows 电脑，Python 3。
- 学生看课件能自学：每个知识点写成完整、口语化的句子，不只放关键词。
- 老师能照着课件读：句子读出来要顺口，老师不用另备一份讲稿。
- 只讲这节课用得上的内容。较深的知识点放到“这些后面再学”这一页，只提一句，不展开。
- 用生活里的比方解释概念，比如“变量是贴了名字的盒子”。比方要准确，不能为了好懂说错。
- 慎用“只能”“所有”“一定”。只有确实成立时才这样说；讲报错要写清在什么情况下才会出现。
- 第一次讲一个概念，说法到后面也要成立。暂时不讲的情况写明范围，不要说成通用规则。

## 一节课怎么安排

按这个顺序，一页只讲一件事。页数不用为了凑少而压缩内容，但页面太多时要分集：

1. **封面**：一个大标题，一句话说清学完能做什么。
2. **它有什么用**：用一个孩子熟悉的例子引出本课。
3. **最小例子**：先给能运行的最短代码，再解释语法。
4. **猜一猜**：先让学生预测，再一步步揭晓。优先选最容易想错的地方。
5. **小测**：每讲完一个知识点就做一道小题，点选后马上解释为什么对或错。
6. **动手改一改**：在例子上做小改动，页面不给完整答案。
7. **主线例题**：一道题，用逐步追踪看清每一行怎么运行，变量怎么变。
8. **常见错误**：教学生读报错，再玩一次“点出有问题的那一行”。错误代码标明“只阅读”。
9. **自己挑战**：一道没讲过解法的新题，下一页是一条一条点开的提示。重写讲过的题或只换数据，不算新题。
10. **造一个你的小程序**：开放的小项目，学生自己定主题，没有标准答案。底线只有一条：先说清程序要做什么，再试两组输入，一组试边界。
11. **和同桌换着玩**：互相运行，说一个喜欢的地方，提一个想法，再改一版。
12. **说得清吗**：三个问题一开始就全部显示，学生先自己说，答案再一条一条揭晓。
13. **速查卡**：本课语法一页看完。
14. **这些后面再学**：预告，不展开。
15. **谢谢**：模板自动生成，不用写。一句欢迎交流的话、课程仓库的 GitHub 链接和下一课入口，不写老师姓名，文案和链接在 `site.json` 里改。

这是我们自己的课堂结构，以它为准。第 10 步“造一个你的小程序”要分成“先做到”“选你喜欢的”“还想更厉害”三层，让谁都能开始、学得快的能走远。

### 页面太多时分上下集

- 一节课超过约 30 页，或一次讲不完，就分成上集和下集，内容特别多时再加中集。
- 在知识点的自然断点切开，不要把一个例题切成两半。
- 每一集都是完整的课件：有自己的封面、小测、动手题和复盘。“造一个你的小程序”放在最后一集。
- 下集用一页回顾上集的要点，再接着讲。回顾只放真正用得上的内容。
- 题目不重复，上集讲过的例题不算下集的独立挑战。

## 互动

- 代码页放“▶ 在 IDE 打开”，动手和挑战页放“▶ 在 IDE 开始改”，带着代码跳到 JupyterLite。挑战页只带注释，不带答案。
- 每节课至少有：预测揭晓、选择小测、点行找错、分层提示。
- 只改一个值、结果一眼能看到的地方可以用黄色框，省掉打开 IDE 的时间。每节课最多 3 处，放在 IDE 动手之前。要先让学生猜再改，改了要能学到东西，比如 0、边界、引号里的 3 + 4。多行输出、循环、改结构、读报错、运行完整程序，或者做起来复杂、容易出错的，都用 IDE。
- 找错题要问得只有一个答案。问题牵涉几行时，换个问法，比如“这个输入走进了哪条路”。
- 挑战题要让本课新学的东西派上明确用场，学生说得出为什么这样写。不用它也能做出来不要紧，用它要更清楚、更省事；用不用都一样的就换题。
- 挑战只比例题多一个难点，新的东西一次只加一样。汉诺塔这种一下加好几样的，放到“后面再学”。
- 学生页上把题面写全：输入几行、每项范围、输出格式、特殊情况（找不到、一样大、重复）和完整样例。不在页面上用省略号代替输出，也不要让老师去 tasks.json 里查。
- 从上一版程序改出下一版时，用代码变化动画：同一个编辑器里，翻一步就从旧版变成新版，学生看得到改了哪几行。适合加一行、改一处、把重复的几行改成循环、外面再套一层循环、在上一题上加条件、把错的写法改对，以及前后两页只差几行的程序。
- 前后两页只差几行、讲的是同一件事（先猜旧版，再改一处猜新版；先看错的，再看改对的），就合并成一页：先走完旧版的几步，再播放变化，接着讲新版。上一页的程序拿来当这一页例题的起点，就在这一页开头放旧版，翻一步变成例题，再一步步讲。
- 不用动画的：全新的程序；改动超过一半的；左右两栏同时对照、两边输出要放在一起比的（比如 if 和 while、缩进和不缩进）；找错题（答案是点出来的，不是翻出来的）；黄色框页；中间隔着别的程序的两页；只是为了好看的。宁缺毋滥。
- 合并页的打印版只留最后一步，所以最后一步的说明要把新旧两版的差别说全。旧版是这节课的主要例题时，在旧版那一步另放一个带它进 IDE 的按钮，因为页面的 IDE 按钮总是带新版。
- 动画只用来讲清楚变化，不做纯装饰。不加吉祥物。

## 放映界面

这些由模板提供，每节课都自动带上，不要在页面里重做：左侧缩略图、底部彩色时间轴、章节跳转、页码跳转、一键打开 IDE、全屏、黑屏和快捷键帮助。写课件时只需给每章第一页标上章节名。

## 版式

- 16:9 固定舞台，1920×1080，一页一个主体，不用“标题加要点加侧栏”的 PPT 结构。
- 风格是暖米白纸面配深色编辑器，代码像真的编辑器：文件标签、行号、语法高亮。
- 字体用内嵌 JetBrains Mono，中文用微软雅黑。标题前加 `#`。
- 颜色表示这页要做什么：米白和深色是听讲，琥珀是动手，陶土红是挑战，橄榄绿是复盘。
- 正文不小于 32px，代码不小于 44px。

## 硬性要求

- 一律用相对路径，不写绝对路径。
- 课件要能离线双击打开，所有样式和脚本都写在页面里。只有 IDE 和官方文档需要联网。
- 页面上的程序必须真实运行过，页面说的输出和报错都要用真实 Python 验证。
- 小改写和挑战的完整答案不能出现在学生页面和发给学生的文件里。
- 每道题要有普通和边界测试数据。数据范围、输入行数和输出格式要写在学生看得到的地方。
- 首轮不用 `eval`；`split`、`map`、推导式要先讲再用；多个输入先分行读入。
- 不按上课时长切分，不写“几分钟”。
- 课件是上课讲的，不写“必做”“选做”“作业”这类字样，题目也不分等级。课后作业老师另外布置。

## 交付前自查

- 零基础学生只看页面，能不能看懂？
- 老师照着读，顺不顺口？
- 每个知识点后面有没有互动？
- 有没有哪页只是在堆文字？
- “造一个你的小程序”的三层是否都有路可走？
- 每章第一页都写了章节名吗？
- 页面太多时分上下集了吗？
